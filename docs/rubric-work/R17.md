# R17 AI Agents와 MCP 연동

결론: Claude Code headless agent가 oneM2M, MEC, Audit MCP 서버 3개를 통해 실제 Mobius4 CSE에서 방문자 위치 접근 workflow를 수행했고, 실행 중 강제 종료 뒤 저장된 run 상태에서 이어서 완료함.

## 목표 기준

- Expert 기준: agent가 여러 도구와 MCP 서버를 조율하고, 지속 상태와 단계 routing으로 oneM2M/MEC workflow를 실행함.
- 과제: visitor-v1에게 household-h1의 keyring-x 위치를 incident-i42 동안 30분 조회 권한으로 부여함. 순서는 기기 발견, grant 조회, 최소 권한 초안, guardian 승인 요청, 적용, MEC 조정, 감사 기록임.

## 구현 내용

| 구성 | 파일 | 역할 |
|---|---|---|
| agent 도구 계약 | `pc-mobius/contracts/mcp-agent-tools.v1.json` | 서버 3개, 도구 8개, workflow 단계, 승인 gate 정의 |
| workflow ledger | `pc-mobius/integration/src/mcp-orchestrator.mjs` (`McpAgentWorkflow`) | 단계 순서 routing, checkpoint, resumePoint, guardian 결정, approvalHash 검증 |
| domain adapter | `pc-mobius/integration/src/mcp-agent-tools.mjs` | oneM2M SDT discovery(`fu=1`, `ty=28`, binarySwitch `cnd`), ACP와 grant 기록, `MecAdapter` Location 조회, run token 발급, 서버 기동 |
| MCP 서버 확장 | `pc-mobius/integration/src/mcp-http.mjs` | session 기반 context(`resolveContext`), reason code가 붙은 `isError` 결과, commit 뒤 hook |
| fixture | `pc-mobius/integration/src/mcp-agent-fixtures.mjs` | 단위 시험용 oneM2M/MEC fixture, MEC 013 Location simulator |
| runner | `pc-mobius/scripts/run-mcp-llm-agent.mjs` | CSE, DB, simulator 기동, `claude -p` 실행, 강제 종료와 재개, guardian 단계, 최종 readback, receipt 작성 |
| 단위 시험 | `pc-mobius/test/mcp-agent.test.mjs` | routing, 승인 gate, 재개, HTTP wire, 실제 adapter 시험 4건 |

- 승인 경계: agent token scope는 `bubble:read`, `bubble:command`, `mec:location`, `audit:read`, `audit:write`로 구성됨. `policy:approve`는 guardian principal에만 있음. `applyApprovedPolicy`는 현재 draftHash에 결속된 guardian approvalHash만 받음.
- context 결속: 서버가 run token에서 runId, grant revision, audience, deadline, operationKey를 만들고 client `_meta`는 무시함.
- 최소 권한: ACP `pv`는 visitor AE 1개에 `acop` 2(RETRIEVE)이고 `et`는 승인 시각에 30분을 더한 값임. 이 ACP는 keyring-x location container의 `acpi`에만 붙음.
- 재개: 도구 commit과 checkpoint가 같은 store transaction에 기록됨. 새 runner는 같은 상태 파일에서 resumedFrom을 기록하고, 새 agent session은 `readExecution`의 nextStep으로 진행함.
- 보존 필드: grant 기록에 grantId, grantRevision, deadline(notAfter), draftHash, approvalHash, payloadHash가 함께 있음.

## 남은 과제

- 운영 MEC 연결: 실제 MEC Location endpoint와 provider 인증서가 필요함.
- 보호자 앱 승인: 앱이 approvals container를 구독하고 guardian 결정 API를 호출하는 연결이 필요함.
- 운영 전송 보안: agent 프로필 서버에 `run-mcp-servers.mjs`의 TLS 1.3과 OIDC verifier를 적용하는 설정이 필요함.
- 만료 시험: ACP `et` 이후 visitor 조회가 4103으로 바뀌는지 보려면 짧은 기간의 추가 실행이 필요함.
- 대시보드 표시: MCP run 상태와 approvalChecks를 웹 이벤트로 보내는 연결이 필요함.
