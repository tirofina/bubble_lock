# R17 AI Agents와 MCP 연동

결론: 결정론적 routine model이 PANIC보다 먼저 이상 징후를 잡고, Claude Code headless triage agent가 oneM2M, MEC, Audit MCP 서버 3개에서 경보마다 다른 도구를 골라 맥락을 모은 뒤 보호자 알림을 보냄. 실제 ETSI MEC Sandbox `dayofcare`의 6개 사례(최종 run 3)에서 오경보 0건, 놓침 0건이고, 갈림길 사례의 보호자 알림이 PANIC보다 265초 앞섬. 같은 사례에서 단일 체류 5분 기준선은 오경보 12건과 놓침 1건, 10분 기준선은 오경보 10건과 놓침 2건임. 장소 기억(암호화 저장, 학습 gate, 동행 판정)을 더한 14일 학습 실험에서 오경보는 1일차부터 7일차 1건, 8일차부터 14일차 0건이고, 반복된 갈림길 배회 3회는 모두 경보로 남음.

## 목표 기준

- Expert 기준: agent가 여러 도구와 MCP 서버를 조율하고, 지속 상태나 고급 routing으로 복잡한 oneM2M/MEC workflow를 실행함.
- 역할 분담: 이상 징후 판정과 보호자 알림 여부는 결정론적이고 측정 가능한 규칙이 맡음. LLM agent는 상황마다 달라지는 맥락 수집, 도구 routing, 알림 단계(checkIn, emergencyLease) 선택, 보호자용 설명을 맡음. 신호 끊김(SIGNAL_GAP)처럼 데이터 품질 경보는 agent가 맥락을 보고 observe로 정리함. lease 적용, 좌표 보호, 승인 hash 검사는 서버가 맡음.
- 제품 목표: 거주자가 주황색 PANIC 버튼을 누르기 전에 보호자가 먼저 알림을 받음.
- 기존 방문자 위치 위임 흐름(승인과 재개)은 오후 돌봄 위임 단계로 이 문서 끝에 유지함.

## 시나리오

70대 후반 거주자가 16:30에 집을 나와 Boulevard de Belgique를 따라 Parc Princesse Antoinette로 걸음. 딸(보호자)은 Fontvieille 사무실에 있음. 평소에는 남쪽 벤치에서 쉬고 산책로를 짧게 돈 뒤 17:24 무렵 귀가함. 이야기의 날에는 귀갓길 17:09, 해가 진 뒤(일몰 17:02) trail fork에서 멈추어 주위를 둘러보고 갈래길 사이를 오가다가 17:18에 PANIC 버튼을 누름.

| 단계 | 담당 | 내용 |
|---|---|---|
| 1 | routine AE (결정론) | oneM2M 위치 이력에서 배운 routine과 오늘 경로를 비교하고, 기준을 넘으면 거주자 AE의 `alerts` container에 alert cin(점수, feature, 구간, 시작 시각)을 씀 |
| 2 | triage AE | `alerts` 구독 알림으로 깨어나 triage run을 만들고 agent를 실행함 |
| 3 | LLM agent | MCP 서버 3개에서 경보 종류에 맞는 도구를 골라 맥락을 모으고 `submitTriage`로 severity, action, 보호자용 설명을 기록함 |
| 4 | 서버 | checkIn과 emergencyLease는 incident를 열고 guardianInbox에 알림을 씀. lease는 보호자가 정확한 draftHash를 승인한 뒤에만 적용함 |
| 5 | incident service | PANIC이 오면 열린 incident를 escalation하고 선행 시간(PANIC 시각 빼기 첫 보호자 알림 시각)을 기록함 |

## routine model

정상 산책 7일(합성, seed 고정)을 거주자 AE의 `locationHistory` container에 기록하고, routine AE가 CSE에서 다시 읽어 profile을 만듦. 정밀 궤적은 AES-256-GCM 암호화 참조로 저장하고 cin에는 소수 셋째 자리 격자만 둠.

| feature | 계산 | 가중치 |
|---|---|---|
| 체류(dwell) | 반경 35 m 정지 구간의 길이를 그 장소의 평소 p95(최소 120초)로 나눈 비율, 1.5배 초과분까지 선형 | 0.40 |
| 왕복(pacing) | 8 m 이상 이동 사이 방향 전환 135도 초과 횟수, 3회에서 최대 | 0.20 |
| 경로 이탈 | 평소 corridor 밖에 머문 시간, 180초에서 최대 | 0.15 |
| 시간 맥락 | 일몰 15분 전부터 30분 동안 증가, 또는 평소 귀가 p95를 지난 분 | 0.15 |
| 집과 거리 | 800 m에서 최대 | 0.10 |

- WANDERING: 체류 비율 1 이상 또는 이탈 120초 이상이고 점수 0.45 이상일 때 발생함. 장소 기억을 쓰면 혼자이고 낯선 곳에 300초 이상, 집에서 400 m 이상일 때도 발생함(novelty).
- SIGNAL_GAP: 위치 cin이 끊긴 시간이 max(120초, 그 구간 평소 gap p95의 1.5배)를 넘을 때 발생함.
- DEVICE_SEPARATION: 키링 BLE를 집 gateway가 보고 있고 relay UE가 집에서 150 m 밖에 120초 이상 있을 때 발생함.
- 경보는 산책마다 종류별 1회이고, 같은 표본을 다시 넣으면 같은 점수가 나옴(단위 시험에서 확인함).
- 단일 체류 기준선은 마지막 위치에서 반경 35 m 안의 시간이 5분 또는 10분을 넘으면 경보함. 집 반경은 제외하고, 표본이 끊긴 동안에도 시계가 흐르며, 다시 움직이면 재무장함.
- dayofcare profile: 평소 출발 16:31, 귀가 p50 17:24와 p95 17:31, 남쪽 벤치 체류 p50 1140초와 p95 1540초, 대로 구간 gap p95 120초, park edge loop는 7일 중 2일에서 4일 corridor임.

## 장소 기억

- 장소: 120초 이상 정지한 구간의 중앙 위치를 반경 45 m 안의 기존 장소에 가중 평균으로 합치고, 없으면 새 장소를 만듦. 장소마다 방문 수, 4시간 단위 시간대와 요일별 방문, 체류 분포(최근 40회), 장소 사이 전이 행렬을 둠.
- corridor: 장소 사이에 지난 30 m cell을 산책마다 1회 세고, 주변 8칸까지 친숙도에 반영함.
- 망각: 모든 가중치에 반감기 21일의 지수 망각을 적용함. 친숙도는 가중치 2에서 1이 되고 0.4 이상을 familiar로 봄.
- cold start: 혼자 정상 종료한 산책이 5일 미만이면 novelty를 끄고, 체류 최소 기준을 600초, 경보 점수 기준을 0.55로 올림.
- 점수: 장소 기억이 경로 이탈(낯선 곳)과 장소별 체류 기준을 제공하고, 나머지 feature와 가중치는 위 routine model을 그대로 씀.

## 암호화 저장

- 장소와 corridor는 routine service 안에서만 평문이고, 저장 형태는 거주자 AE `routine` container의 `PLACE_MEMORY` cin(AES-256-GCM ciphertext, AAD `place-memory:<residentId>`, state hash 포함)임.
- 키 관리는 location-privacy.mjs와 같은 `MecCipher` 방식(서비스 저장소 옆 32바이트 키 파일, 권한 0600)이며, 키는 routine service 저장소에만 있음.
- agent와 MCP 도구가 받는 정보는 같은 container의 `PLACE_SUMMARY` cin 하나임. 내용은 장소 이름표("familiar south bench", "familiar Fontvieille cafe", "unfamiliar area"), 친숙도, 방문 수, 시간대, 체류 분 단위, 보호자 OK 표시, 거리 구간(near home, neighbourhood, park range, far)임. `readAlert`는 경보 장소의 이름표, 친숙도, 거리 구간을, `readRoutineProfile`은 요약을 돌려줌.
- 실행 확인: 학습 실험에서 매일 봉인한 memory cin 14개와 sandbox 단계 cin 4개 모두 triage AE(RETRIEVE 권한)로 다시 읽어 좌표형 숫자 0건, 복호화 뒤 state hash 일치를 확인함.

## 학습 gate

- solo-normal 기억은 혼자 나가 정상으로 끝난 산책(경보 없음, 또는 보호자가 경보를 OK로 닫음)과 보호자의 "이 장소는 괜찮음" 표시로만 갱신함.
- 동행 산책은 별도 accompanied 저장소에 쌓고, 혼자 산책의 친숙도 계산과 분리함.
- PANIC이 있었던 산책과 보호자가 닫지 않은 경보 산책은 학습에서 제외함. 그래서 반복된 혼란 배회는 계속 낯선 행동으로 남음.

## 동행 판정

- MEC 동행: 거주자 relay UE와 보호자 UE가 같은 MEC013 zone에 있고 50 m 이내이며 방향과 속도가 비슷한 보고가 3번 연속이면 동행으로 봄.
- BLE 동행: 보호자 폰이 키링을 BLE로 보면 동행으로 봄. 이번 실행에서 이 신호는 시뮬레이션 플래그이고 receipt에 simulated로 표시함.
- 동행 중에는 novelty와 거리 기반 경보를 멈춤. PANIC은 항상 동작함. 혼자이고 멀거나 낯선 곳이면 경보함.

## 동의와 개인정보

- 거주자 동의: routine 학습과 위치 기반 판정은 거주자의 동의(가구 consent와 grant)로 동작하고, 거주자나 보호자가 학습을 멈추거나 저장된 장소 기억 cin을 삭제할 수 있어야 함. 삭제 경로는 routine container의 memory와 summary cin 삭제와 서비스 키 폐기로 구성함.
- 보호자 동의: MEC 동행 판정은 보호자 UE 위치를 쓰므로 보호자 본인의 별도 동의가 필요함. 동행 판정에 쓴 보호자 위치는 판정 결과(동행 여부, 이유, 연속 보고 수)만 남김.
- BLE 근접 방식은 보호자 폰이 키링을 보았는지만 쓰므로 보호자 위치 없이 동작하는 선택지임.
- 보호자 lease: 정밀 위치는 보호자가 정확한 draftHash를 승인한 5분 lease 동안만 열림.

## triage agent와 MCP 도구

| 서버 | 도구 | 연결 |
|---|---|---|
| oneM2M | `readAlert`, `readRecentHistory`, `readRoutineProfile`, `readDeviceState` | 실제 Mobius4의 alerts, location, routine, keyring state와 events container를 triage AE originator로 읽음 |
| oneM2M | `submitTriage`, `draftLocationLease`, `requestGuardianApproval`, `applyApprovedLease` | triageLog, incidents, guardianInbox, approvals, leases container에 cin을 씀 |
| MEC | `queryUeLocation`, `queryZoneStatus`, `queryServingCell` | ETSI MEC Sandbox MEC013 v3 `queries/users`, `queries/zones/{zoneId}`, MEC012 `rab_info`, 고정 CA HTTPS |
| Audit | `readExecution`, `appendTriageEvidence` | 지속 run ledger, audit container의 evidenceHash |

- Claude Code는 `claude -p --output-format stream-json --mcp-config <run config> --strict-mcp-config --tools "" --allowedTools <MCP 도구 13개> --permission-mode dontAsk`로 실행하고, model은 사용자 기본값을 따름(`--model` 인자 생략).
- system prompt는 도구의 쓰임새와 action 3종을 설명하고, 경보 종류별 도구 선택은 agent의 판단에 맡김.
- 서버 검사: `readAlert` 전 `submitTriage`는 `ROUTE_ORDER`, observe나 checkIn 뒤 lease 도구는 `ROUTE_ACTION`, 읽기 15번째 호출은 `ROUTE_BUDGET`, 설명 안 좌표형 숫자는 `EXPLANATION_PRIVACY`, action과 severity 불일치는 `ACTION_SEVERITY`, 최소 action 미만은 `ACTION_FLOOR`, 보호자 결정 전 apply는 `APPROVAL_PENDING`임.
- 최소 action: WANDERING과 DEVICE_SEPARATION은 checkIn 이상임(`workflow.actionFloor`). `readAlert`가 `minimumAction`과 이유를 함께 알려 줌.
- `readRecentHistory`는 구간 이름의 흐름과 함께 서버가 계산한 정지 구간(장소, 시작과 끝, 방향 전환 수)을 돌려줌.
- lease: 보호자 수신, 목적 wandering-check 또는 emergency-rescue, 5분 이하만 findings 없이 통과함. 보호자가 정확한 draftHash를 승인하면 triage AE가 저장된 run 상태(디스크 상태 파일의 nextStep)에서 LLM 없이 `applyApprovedLease`와 evidence를 실행함. 적용은 `LocationPrivacyService.createLease`임.
- 시간 모델: 재생 중 시나리오 시계는 20초 표본 격자를 따르고, triage 동안에는 실제 속도로 흘러 CSE 알림, agent, 보호자 단계의 지연이 그대로 더해짐. PANIC은 triage 중이라도 시나리오 시각에 전달함.
