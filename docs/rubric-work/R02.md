# R02 통신 프로토콜의 조건별 선택

결론: 키링은 BLE GATT, Gateway는 MQTT(기본)와 HTTPS(조건별), 앱은 HTTPS 알림과 HTTPS 조회를 사용함. 2026-11-19 단일 PC 실행에서 Gateway 전체 데몬이 브로커 재시작, CSE 쪽 MQTT 단절, 큰 묶음 조건마다 경로를 바꾸었고 관측 509건이 손실 0건, 중복 0건으로 CSE에 저장됨.

- 실행 기록: [protocol-matrix-real-cse.json](../verification-evidence/2026-11-19/protocol-matrix-real-cse.json) (status PASS, runId `1795090210814_c49d3d`, gitHead `1850bff`)
- 전이 구간 trace: [protocol-matrix-trace.jsonl](../verification-evidence/2026-11-19/protocol-matrix-trace.jsonl) (브로커 연결과 구독, PUBLISH와 전달, HTTPS 요청, Gateway 경로 변화)
- 실행 스크립트: `pc-mobius/scripts/run-protocol-matrix-real.mjs`, Gateway 하네스 `keyring/raspberry-pi-gateway/cse_integration_tests/protocol_matrix_daemon.py`

## 실행 구성

| 구성 요소 | 구분 | 내용 |
|---|---|---|
| 키링 24대 | 모의 | Bleak GATT 클라이언트 경계에서 에뮬레이션함. 펌웨어와 같은 LF 구분 JSON을 20 B 알림 조각으로 보냄. 제품 `BleFleet` 파서가 그대로 해석함 |
| Gateway 0.2.44 | 실제 | `Gateway.run()` 전체 작업자(자격 조회, 명령 조회, 실행, outbox, health)와 실제 SQLite |
| MQTT 브로커 | 실제 | aedes 1.2.0, MQTT 3.1.1. Gateway용 TLS 1.3 + 클라이언트 인증서 리스너, CSE용 loopback TCP 리스너 |
| CSE | 실제 | Mobius4 4.24.5, PostgreSQL 17.6 + PostGIS. 앞단 TLS 1.3 + 클라이언트 인증서 프런트 |
| 중앙 API | 실제 | `pc-mobius/scripts/run-integration-api.mjs`, mTLS |
| 앱 | 실제 | HTTPS 알림 수신 서버, HTTPS 조회 클라이언트 |

호스트 1대, 모든 연결은 loopback임. 인증서는 실행마다 새로 만든 ECDSA P-256 시험 인증서이고 `.local/` 안에서 실행 후 삭제함. 네 TLS 링크 모두 TLSv1.3, TLS_AES_256_GCM_SHA384로 측정됨.

Gateway는 CSE 관리자 ID 대신 등록한 자기 AE-ID로 접근함. HTTPS 프런트는 인증서 CN과 `X-M2M-Origin`을, 브로커는 인증서 CN과 토픽을 묶음. 앱 인증서로 Gateway originator를 쓰는 요청은 403으로, 앱 AE의 관측 생성은 ACP에서 4103으로 거절됨. 앱 AE의 구독 생성도 4103이므로 구독은 컨테이너 소유자인 Gateway AE가 만들고 알림 대상은 앱 서버로 지정함.

## 구간별 프로토콜 선택

| 구간 | 프로토콜 | 선택 이유 | 이번 실행 측정값 | 대체 경로 |
|---|---|---|---|---|
| 키링 → Gateway | BLE GATT 알림, 20 B 조각, 인증된 bond | 저전력 단거리 무선, 장치는 GATT 특성 읽기와 알림만 구현함 | 관측 프레임 210 B, 알림 11개, 공중 전송 추정 441 B | BLE 재연결 backoff, sequence 기준 중복 제거 |
| Gateway → CSE 관측(기본) | oneM2M MQTT 바인딩, TLS 1.3, QoS 1, `/oneM2M/req/<AE-ID>/Mobius4/json` | 지속 세션 하나로 작은 프레임을 연속 전송, TLS 연결 비용은 세션당 한 번 | publish RTT p50 3.1 ms, p95 4.8 ms. 관측당 1,534 B(PUBLISH 701 B, 응답 766 B, PUBACK 4 B, TLS 레코드 포함) | 아래 세 조건에서 HTTPS |
| Gateway → CSE, 브로커 세션 끊김 | oneM2M HTTP 바인딩, TLS 1.3 | 대기 없이 즉시 전송 | 끊김 감지 1.1 ms, publish RTT p50 4.9 ms, keep-alive 연결에서 관측당 1,948 B | 재연결 후 probe 응답을 받으면 MQTT |
| Gateway → CSE, MQTT 응답 미확인(새 세션, 응답 시간 초과) | HTTPS | CSE 재구독 전 구간의 데이터를 바로 HTTPS로 저장함 | 15초 단절 동안 대기 1건(3.0 s), 이후 HTTPS 104건(RTT p50 4.9 ms) | MQTT RETRIEVE probe, 5 s부터 두 배씩 300 s까지 |
| Gateway → CSE 큰 묶음(health, 자격 전환 영수증) | HTTPS | primitive 4,096 B 초과 묶음은 HTTPS로 보내 MQTT 세션을 작은 관측 전용으로 유지함 | health 5.7 KB 16건, 자격 전환 영수증 5.7 KB 1건, 모두 HTTPS, RTT p50 7.8 ms | HTTPS 고정 |
| Gateway ↔ 중앙 API | HTTPS REST, mTLS | 자격 상태, 명령 목록, 실행 승인은 요청과 응답이 짝을 이루는 동기 호출 | 15초 자격 조회와 2초 명령 조회 합계 약 368 B/s | 조회 실패 시 명령 실행 보류 |
| CSE → 앱(push) | oneM2M HTTP 알림, TLS 1.3 | 새 관측을 앱에 즉시 전달 | 알림 533건, 본문 741 B, 알림당 수신 1,072 B | 앱 HTTPS 조회 |
| 앱 → CSE(조회) | oneM2M HTTP 조회, TLS 1.3 + 클라이언트 인증서 | 화면 진입과 재동기화 때 최신값 조회 | `/la` 조회 213건, p50 3.5 ms, p95 4.9 ms, 요청 222 B, 응답 988 B | 앱 push 알림과 병행 |
| 앱 실시간 화면 | SSE(웹 대시보드) | 브라우저 표준 단방향 스트림, `Last-Event-ID` 재개 | 웹 대시보드 fixture 재생 시험으로 확인함 | 수동 재연결 커서 |

장치와 앱의 프로토콜이 서로 다름: 키링은 BLE GATT만 쓰고, Gateway가 MQTT와 HTTPS를 고르며, 앱은 HTTPS 알림과 조회를 씀.

## 연결 비용과 전송량

| 항목 | MQTT | HTTPS |
|---|---|---|
| 새 세션 1개 준비 | 4,259 B(TLS 핸드셰이크, CONNECT, SUBSCRIBE) | 4,079 B(TLS 핸드셰이크) |
| 연속 관측 1건(200 ms 간격) | 1,534 B | 1,948 B |
| 희소 관측 1건(6초 간격) | 1,537 B, 세션 유지 | 관측 6건 모두 새 TLS 연결(httpx keep-alive 5초 만료), 1,950 + 4,079 = 약 6,029 B |

희소 관측에서 HTTPS 전송량은 MQTT의 약 3.9배임. 연속 관측에서도 HTTPS가 약 1.27배임. loopback 환경의 RTT 차이는 2 ms 안팎이므로 이번 측정에서 프로토콜 선택의 효과는 연결 비용과 전송량에서 크게 나타남.

## 조건별 전환 결과

### 브로커 재시작(10초 중단, 200 ms 간격 관측 200건)

| 항목 | 값 |
|---|---|
| Gateway 끊김 감지 | 1.1 ms |
| 중단 후 첫 HTTPS 저장 | 405 ms(다음 관측 생성과 outbox 0.5초 폴링 포함) |
| Gateway MQTT 재연결과 재구독 | 1.0 s |
| Mobius4 MQTT 재구독 | 4.6 s |
| probe 전송 시각 | 1.0 s(시간 초과), 9.0 s(응답) |
| MQTT 확인, 첫 MQTT 저장 | 9.0 s, 9.4 s |
| MQTT 응답을 기다린 관측 | 0건 |
| 경로 | MQTT 105, HTTPS(세션 끊김) 55, HTTPS(미확인) 40 |
| 손실, CSE 중복, 알림 중복 | 0, 0, 0 |

Gateway가 Mobius4보다 3.6 s 먼저 재연결함. 새 세션 probe가 이 구간의 관측을 HTTPS로 보냄.

### 장기 중단과 희소 관측(37초 중단, 6초 간격 6건)

관측 6건 모두 HTTPS로 저장됨. 재시작 후 Gateway 재연결 2.0 s(paho backoff), Mobius4 재구독 22.3 s, probe 2.0 s, 10.0 s, 23.0 s 전송, MQTT 확인 23.0 s임. MQTT 확인은 CSE 재구독 0.7 s 뒤임.

### CSE 쪽 MQTT 단절(브로커가 CSE 방향 전달을 15초 차단, 200 ms 간격 관측 225건)

| 항목 | 값 |
|---|---|
| 차단 후 첫 MQTT 요청과 응답 시간 초과 | 0.3 s에 전송, 3.0 s 대기 후 같은 자원 이름으로 HTTPS 저장 |
| 이후 HTTPS 관측 | 104건, RTT p50 4.9 ms, p95 5.8 ms |
| probe 전송 시각(차단 시작 기준) | 8.3 s(차단됨), 21.3 s(응답) |
| 차단 해제 후 MQTT 확인, 첫 MQTT 저장 | 6.3 s, 6.4 s |
| 경로 | MQTT 120, HTTPS(시간 초과 후) 1, HTTPS(미확인) 104 |
| 손실 | 0건 |

응답 시간 초과를 기다린 관측은 1건이고 나머지는 HTTPS로 바로 저장됨. 미확인 경로의 BLE 수신부터 앱 알림까지 지연 p95 1.8 s는 이 대기 뒤에 쌓인 관측에서 나옴.

### 큰 묶음

24대 장치 상태를 담은 health(5.7 KB)와 자격 전환 영수증(5.7 KB)은 MQTT 세션이 정상인 동안 `https_large` 경로로 저장됨(health 10건, 영수증 1건). 브로커 중단과 미확인 구간의 health 6건은 해당 구간 경로로 저장됨.

| MQTT(303건) | 3.1 / 4.8 ms | 223 / 427 ms | 222 / 427 ms |

## 무결성

| 항목 | 값 |
|---|---|
| 에뮬레이터 관측 + 연결 시 READ 관측 | 509 + 24 = 533건 |
| CSE 컨테이너 `cni` | 533 |
| 앱 AE의 개별 readback(장치, 부팅 ID, sequence) | 509 / 509 일치 |
| 앱 알림 | 533건, 중복 0건 |
| 4105 충돌 흡수 | MQTT 0, HTTPS 0 |
| 종료 시 outbox 잔여 | 0 |

자원 이름은 `gw-<sha256(rqi)>`로 고정되므로 MQTT 시간 초과 뒤 HTTPS 재전송도 같은 자원을 가리킴.

## 제품 변경(Gateway 0.2.44)

- `TransportHub._native_route()`가 요청마다 경로를 고름: 설정, 브로커 세션 상태, MQTT 응답 확인 상태, primitive 크기 순서임.
- 새 브로커 세션이 열리면 관측 컨테이너 RETRIEVE probe를 즉시 MQTT로 보내고, 응답을 받을 때까지 데이터를 HTTPS로 보냄.
- MQTT 응답 시간 초과 뒤 해당 요청은 같은 자원 이름으로 HTTPS에 저장하고, probe 간격 `MQTT_PROBE_INTERVAL_SECONDS`(기본 5초)를 300초까지 두 배씩 늘림.
- `MQTT_MAX_PAYLOAD_BYTES`(기본 4096, 키링 BLE 프레임 상한과 같은 값)를 넘는 primitive는 HTTPS로 보냄.
- 경로별 횟수(`native_mqtt`, `native_https_*`, `mqtt_probe*`)를 health `counters`에 남김. 실행 종료 시 값: MQTT 328, HTTPS 큰 묶음 11, 세션 끊김 65, 미확인 146, 시간 초과 1, probe 8회(응답 4, 시간 초과 4).
- 단위 시험 11개 추가, 기본 suite 167개 통과.

## 재현 방법

```sh
npm run setup
export MOBIUS4_ROOT=<Mobius4 4.24.5 경로>
node pc-mobius/scripts/run-protocol-matrix-real.mjs
```

`.local/postgres/connection.json`의 PostgreSQL에 실행 전용 DB를 만들고 종료 시 삭제함. aedes 1.2.0은 처음 실행 때 `.local/protocol-matrix/broker`에 설치됨(integrity 값은 실행 기록에 있음). 실행 시간은 약 6분임. 원본 로그(브로커, HTTPS 프런트, 알림, Gateway, Mobius4)는 `.local/protocol-matrix/runs/<runId>/`에 남음.

## 한계

- 키링은 에뮬레이션임. GATT 전송 시간, 무선 손실, BlueZ 동작은 실물 키링과 Pi에서 같은 행렬로 다시 측정해야 함. BLE 공중 전송 바이트는 펌웨어 조각 규칙으로 계산한 값임.
- 호스트 1대의 loopback 측정임. 지연 값은 loopback 왕복 시간을 담고, Wi-Fi와 LTE 값은 실물 측정이 필요함. 바이트는 TCP 페이로드 기준이며 TLS 레코드를 포함함.
- Mobius4 4.24.5는 QoS 0으로 구독하고 응답함. QoS 1은 Gateway와 브로커 구간에 적용됨. 종단 신뢰성은 rqi 응답 대조, SQLite outbox 재시도, 고정 자원 이름으로 확보함.
- CSE 쪽 MQTT 단절은 브로커가 CSE 방향 전달을 버리는 방식으로 만든 조건임. 브로커 재시작은 프로세스 수준의 중단과 시작이고 세션 상태는 메모리에만 있음.
- 앱 SSE 경로는 웹 대시보드 fixture 재생 시험으로 남아 있음. 실시간 SSE 측정에는 CSE 알림을 받아 SSE로 내보내는 이벤트 게이트웨이 연결이 필요함.
- 운영 PKI, 운영 브로커 ACL, 실제 Pi 배포에서의 같은 측정은 다음 단계임.
