# R14 연합학습 oneM2M 조정 평면

oneM2M CSE를 연합학습(Federated Learning, FL)의 조정 평면(coordination plane)으로 쓰는 구현과, 실제 Mobius4 위에서 coordinator와 worker를 별도 OS 프로세스로 띄운 12라운드 실행 receipt를 갖춤. 실행 위치는 로컬 호스트 1대이며, ESTIMED VM과 샌드박스 VM 실행은 `R14-estimed-deploy.md` 절차로 이어갈 다음 단계임.

DOC-REV 2.0.0, 참조 문서 oneM2M TR-0084. 자원 이름과 content schema는 이 저장소에서 정의함.

## 구성

### 자원 배치

FL 작업 하나가 FL AE 하나에 대응함. 모든 cin content는 `urn:privacy-bubble:fl-plane:<kind>:1` schema, `payloadHash`, Ed25519 `signature`를 가짐.

| 자원 | 형식 | ACP | 역할 |
|---|---|---|---|
| `/Mobius/acp-<flAe>` | ACP | coordinator ALL, all DISCOVERY | AE 생성 시점의 acpi, label discovery 허용 |
| `/Mobius/<flAe>` | AE | 위 ACP | 작업 단위, lbl `fl-plane:task:<taskId>` |
| `participants` | cnt, mni 1000 | all CREATE | 등록, 동의 변경 inbox |
| `datasets` | cnt | coordinator | 승인된 데이터셋 메타데이터 catalog (행 수, split hash) |
| `tasks/task-v1` | cin | all RETRIEVE, DISCOVERY | 서명된 작업 정의, coordinator 공개키 |
| `currentModel/v-NNNN` | cnt mni 5, cin | 승인 참여자 RETRIEVE | 서명된 전역 모델 (float32 108 byte, base64) |
| `status` | cnt mni 200 | 승인 참여자 RETRIEVE | epoch claim `epoch-NNNN`, 라운드 상태 |
| `rounds/r-NNNN/config` | cin | 승인 참여자 RETRIEVE | 선정 목록, deadline, 기준 모델 hash |
| `rounds/r-NNNN/updates` | cnt, `acp-r-NNNN` | 선정 AE-ID CREATE | worker update cin `u-<participantId>` |
| `rounds/r-NNNN/result` | cin | 승인 참여자 RETRIEVE | accepted set, dropout, 거부 사유, 집계 모델 |
| `/Mobius/flw-<id>/heartbeat` | cnt mni 5 | worker ALL, coordinator RETRIEVE | 서명된 worker heartbeat |

### 프로토콜 순서

1. worker가 사전 할당 AE-ID로 AE를 등록하고, label discovery로 FL AE를 찾고, coordinator 서명을 확인한 작업 정의를 읽음.
2. worker가 운영자 서명 enrollment, 데이터셋 메타데이터, 동의 상태를 담은 등록 cin을 `cr:null`로 씀. CSE가 기록한 creator와 AE-ID 일치를 coordinator가 확인함.
3. coordinator가 inbox를 처리하고 `acp-members`에 AE-ID를 넣음. 승인 여부는 CSE ACP 결과(2000 또는 4103)로 worker에게 드러남.
4. 라운드마다 coordinator가 적격 참여자(동의 ACTIVE, 서명 heartbeat가 TTL 안, enrollment 유효)를 고르고, 선택 횟수가 적은 순, 직전 기준 모델 손실이 큰 순으로 최대 3명을 뽑음. `acp-r-NNNN`이 선정 AE-ID에만 CREATE를 엶.
5. worker가 status를 polling하여 라운드를 찾고, config와 기준 모델을 CSE에서 받아 서명과 hash를 확인함. 받은 모델을 로컬 test split으로 평가하고(연합 평가), 로컬 train split으로 학습하고, update cin을 씀. update에는 모델 벡터, `artifactDigest`(sha256), 학습 receipt, 지표가 있고 원본 행은 worker 프로세스 안에 머묾.
6. coordinator는 subscription notification(net 3)과 polling으로 update 도착을 감지함. 선정자 전원 응답 또는 deadline에 라운드를 닫고, ACP를 coordinator 전용으로 바꾼 뒤, 검증된 update가 quorum(2) 이상이면 기존 `fedAvg`로 집계하여 `result`와 `currentModel/v-NNNN`을 씀.
7. coordinator 재시작 시 `status/epoch-NNNN` create-if-absent로 더 높은 epoch를 확보하고, inbox 재처리, 라운드 config와 result 순회, currentModel 확인으로 상태를 CSE에서 복원함. 더 낮은 epoch 인스턴스는 다음 tick에서 `FL_COORDINATOR_FENCED`로 멈춤.

### 무결성과 데이터 위치

- coordinator 서명 26건 전부 유효함.
- 12개 라운드 모두 CSE에서 다시 읽은 update로 FedAvg를 재계산한 hash가 result의 모델 hash와 일치함.
- 모델 lineage(parentHash 연결) 12단계가 초기 모델부터 마지막 모델까지 연속으로 이어짐.
- CSE content 102건을 검사한 결과 특징 배열과 행 ID 0건, 원본 행은 worker 프로세스 안에만 있음.
- `fl-onem2m-readback.mjs` CLI가 같은 CSE에서 독립적으로 PASS를 냄.

### 기준선 비교

같은 test split, 같은 수치 코드로 하네스가 계산함. 중앙 학습은 4개 train split을 합친 상한 기준이며 원본 데이터 이동이 필요함. 정적 선택 이상형은 모든 라운드에 w1~w3 세 명이 참여하는 이상 조건임. 정적 선택 동일 고장형은 w1~w3을 고정하고 실제 라운드에서 부적격, 결측, 거부된 구성원을 뺌.

### 서버 CSE 실행 (2026-11-20)

- 팀 서버 CSE(Mobius, cseId `/bubble-cse`)에 nginx mTLS 경로 `https://<SERVER_DOMAIN>:8443/onem2m`으로 접속함. X-M2M-Origin은 클라이언트 인증서마다 `Cpb-fl-coord`, `Cpb-fl-w1`~`Cpb-fl-w3`로 고정됨.
- coordinator는 연구실 PC 프로세스, worker 3개는 MEC 샌드박스 VM의 transient systemd 단위(`bubble-fl-worker-w1`~`w3`)로 실행함. runtimeMode `LOCAL_STF685_VM_SERVER_CSE`, 합성 데이터임.
- 6라운드를 모두 완료함. 라운드 3에서 학습 중인 w2를 `systemctl stop`으로 멈추자 deadline과 quorum으로 w1, w3 두 건이 반영되었고, 라운드 4에서 w2가 `HEARTBEAT_STALE`로 제외되었고, 다시 기동한 w2가 라운드 5에 재선정됨.
- 최종 모델 정확도는 w1~w3 합친 test 0.950, 이전 로컬 실행과 같은 480행 test 0.938임(이전 로컬 실행의 라운드 6 값 0.940).
- FedAvg readback 재계산 6건 모두 일치, 서명 오류 0건, update creator와 고정 originator 일치함. receipt는 `docs/verification-evidence/2026-11-20/fl-server-cse.json`이고 trace SHA-256은 `bd7b5c55b7dcd09be93f1d8bfd5c9bb61203582c3b1fb9011b748c9ccd034aeb`임.

## 해석

- 동적 선택은 이상 조건의 정적 선택과 같은 수준의 정확도를 냄(McNemar p=1.00). 같은 고장 일정에서는 정적 선택보다 합친 test 정확도가 1.25pt 높고(p=0.031), seed 10조 평균으로 0.9pt 높음.
- 동적 선택의 이점은 탈락, 철회, 변조가 생긴 라운드에서도 quorum을 채워 학습을 이어가는 회복성과 늦게 합류한 new-device 도메인 반영에 있음. 정확도 상승 폭 자체는 작고 실행마다 고장 대상 worker에 따라 달라짐.
- 중앙 학습과의 정확도 차이는 0.8pt이고 손실 차이(0.392 대 0.274)가 더 큼. 라운드당 2 local epoch, 12라운드 예산에서 연합 모델이 아직 수렴 중임을 보여줌.
- 라운드 4에서 new-device 공변량 이동이 들어오며 오라클 정확도가 0.946에서 0.915로 내려간 뒤 라운드 9 이후 0.94 수준으로 회복함.

## 한계

- 실행 호스트는 로컬 PC 1대이고 CSE 연결은 loopback HTTP임. TLS와 다중 호스트 실행은 `R14-estimed-deploy.md` 절차로 이어갈 단계임.
- 데이터는 문서화된 합성 작업임. 실제 BLE 관측 데이터는 `dataset.source: jsonl` 경로로 같은 worker에 연결할 수 있음.
- 탈락 구간을 재현 가능하게 열기 위해 선정 라운드마다 `trainDelayMs=800` 인공 지연을 둠.
- 철회 참여자 w3의 과거 기여(라운드 2, 3, 4, 5, 7)는 모델 lineage에 남아 있고 receipt에 기록됨. 과거 기여 제거가 필요하면 기존 `FlCoordinator.approveRetraining` 경로처럼 승인 checkpoint부터 재학습하는 정책 연결이 필요함.
- update 벡터 보호에는 secure aggregation과 차등 프라이버시(differential privacy)가 다음 단계 항목임.
- 다중 호스트에서는 heartbeat TTL 판정에 NTP 시각 동기가 필요함.
- Mobius4 4.24.5는 acpi 없이 만든 자원에 비관리자가 acpi를 추가하면 5000(`acpi is not iterable`)을 돌려줌. 이 구현은 CSEBase 수준 ACP를 먼저 만들고 AE 생성 시 acpi를 넣는 방식으로 대응함.
